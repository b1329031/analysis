# 即時串流轉錄（Real-time Streaming ASR）

**即時串流轉錄**是指在語音仍在持續輸入的過程中，近即時地輸出轉錄結果，而非等到錄音結束後才一次性處理。與批次處理（batch processing）相比，核心挑戰是在準確率與延遲之間取得平衡。

## 詳細說明

### 核心挑戰

1. **批次模型的不適配**：如 Whisper 設計用於最長 30 秒完整音訊，不適合串流
2. **分塊邊界問題**：固定視窗切割可能在詞語中間斷開，造成辨識錯誤
3. **延遲與準確率的取捨**：輸出越即時，可用的上下文越少，準確率越低
4. **Whisper 幻覺問題**：空白音訊段可能觸發 Whisper 輸出亂碼（需 VAD 防護）

### 主要技術方案

| 技術 / 工具 | 核心策略 | 延遲 |
|---|---|---|
| [[Whisper-Streaming]] | Local Agreement Policy | ~3.3 秒 |
| [[SimulStreaming]] | 改進的 Local Agreement | 更低（實測數據待補） |
| [[VoiceStreamAI]] | VAD + 靜音等待分塊 | 依分塊長度，預設 5 秒+ |
| GPT-4o Realtime API | 端到端神經網路 | ~200 毫秒 |

### VAD 在串流中的作用

語音活動偵測（VAD）是串流轉錄的關鍵前置步驟：
- **偵測語音邊界**：知道「什麼時候說完了」，決定送給 ASR 的時機
- **防止 Whisper 幻覺**：過濾靜音段，避免空白音訊觸發亂碼輸出（見 [[taiwanese-spoken-lm]] 的 Silero VAD 應用）
- **減少計算負擔**：只在有語音時觸發 ASR

### Local Agreement Policy（Whisper-Streaming）

連續 n 次更新（每次有新音訊加入）都同意某個前綴轉錄時，才確認輸出該前綴：
- 避免固定視窗切割的邊界問題
- 以「多次確認」換取穩定性
- 延遲約 3.3 秒（視設定而異）

## 出現場合 / 使用者

- 會議現場即時字幕
- 語音助理對話（需低延遲 < 500 毫秒）
- 直播字幕生成
- 即時翻譯

## 相關概念

## 備註

- 對話場景（語音助理）需延遲 < 500 毫秒，3.3 秒的 Whisper-Streaming 不適用
- 會議字幕場景可接受 2–5 秒延遲，Whisper-Streaming / SimulStreaming 可行
- 2026 年趨勢：GPT-4o Realtime API 將端到端延遲壓至 200 毫秒，但需 API 費用
